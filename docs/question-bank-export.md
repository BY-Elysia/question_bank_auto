# v1.1 题库导出

JSON 下载与 ZIP 内的题库文件使用同一个 `questionBankExport` 投影。教材存储、编辑、任务和引用继续使用内部稳定 ID；导出通过 `exportIdentities` 建立独立的章节与题目编号映射。

- 章节采用 `ch_章号_节号`，如 `ch_3`、`ch_3_1`；`parentId` 指向转换后的上级章节。
- 优先读取标题中明确的章、节或习题编号。无编号条目按同级目录顺序分配未使用编号；重复编号分配独立编号，避免重复键。`orderNo` 是本级编号，而非全书目录下标。
- 题目按所属节的文档顺序连续编号，如 `q_3_1_1`；共享题干的子题为 `q_3_1_1_1`。题号不从内部哈希 ID 或不连续的图片题号推导。
- GROUP 子题保留 `questionType` 与 `orderNo`，不额外输出 `nodeType`，与参考模板子题字段一致。
- 选择、填空等题型标题归入所属小节，独立题连续计数；不会因为题型标题产生新的分组题。
- 尚未分节的题目归入 `ch_0`。直接挂在非末级章节的题目使用保留的 `0` 段，如 `q_3_0_1`，防止其子题 ID 与节内题目冲突。
- 同一文档重复导出得到相同编号；插入、删除或调整题目顺序后重新编号。导出编号是当前快照中的位置，不替代工作区内部身份。

题干、公式、选项、答案、解析与 GROUP/LEAF 结构不因 ID 转换改变。下载接口保持只读；选择题、填空题的 `rubric` 固定为空数组，不调用评分模型；其他题目必须有三条简洁的得分点，各项 `maxScore` 之和等于 `defaultScore`。课程 ID、教材 ID、出版社等来自用户教材基础信息，未填写的值不会从参考文件复制。

## 评分细则分层与生命周期

`domain/grading.ts` 定义评分项、总分约束、题干/选项/答案指纹及可评分叶子枚举。GROUP 的共享题干参与各子题指纹，组本身不重复计分。评分数据保存在题目领域对象内，不依赖导出时临时拼装。

`fillAnswers` 是答案处理的统一应用用例。教材有答案时，保留原答案和来源，整理答案的同时生成三条评分标准；没有答案时，`answer-generate` 在一次模型响应中输出解析、答案和得分点。选择、填空题输出空评分。两部分一起校验、一起保存检查点、一起进入候选并确认，不发布缺少评分的主观题答案候选。

`answerOutput` 的文本协议为 EXPLANATION → ANSWER → RUBRIC → END。评分分值通过领域层 `allocateScores` 统一分配，总分保持不变。旧版答案任务升级时保留有效候选，但重新检查答案与评分完整性。

`ExportPreparation` 仅校验已保存的数据。`POST /api/textbooks/{id}/export/prepare` 成功返回 `{ready:true, jobId:null, total, missing:0}`；缺失或过期评分返回 422，不启动模型或任务。JSON 与 ZIP 使用相同投影。旧教材通过答案处理任务补齐，下载不承担数据生成职责。独立 `rubrics` 任务保留为已有数据的批量维护接口，不进入常规提取和导出流程。

题干、选项、答案或解析修改后，对应评分指纹失效；题号和审核状态变化不触发重新生成。原始模型输出、用量和错误记录保留在任务中。关闭页面不会终止答案处理任务。

## 接收端兼容

填空题导出为 `FILL_BLANK`，简答和作图题保留 `SHORT_ANSWER`。教材 ID 未填写或只有空白时使用工作区稳定 ID；下载前统一检查教材名称、学科和出版社，缺少时返回 422 并提示修改教材基础信息，不伪造出版社。JSON、ZIP、导出准备共用同一校验。解析保留在 `standardAnswer.explanation`，接收端应持久化并单独展示该字段，不能仅读取 `text`。
