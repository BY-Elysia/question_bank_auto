# 公式首次加载与校对布局优化

部署 e604cc1；2026-11-06，真实服务器、Chrome 新上下文冷缓存、同一教材。导航在 commit 时开始等待图片/公式，二者分别计时，避免把浏览器 load 事件当作首次可见；热测仅刷新一次。此口径比上一轮等待 goto 默认 load 后再检测更准确。

## 瓶颈证据

本轮修改前：公式脚本在 7.040 秒才开始下载，14.599 秒结束；公式可见 15.031 秒，字体等待到约 18.255 秒。记录中只有一次 50ms 主线程长任务。主要瓶颈是 App → 整份工作区 JSON → Review/KaTeX → 字体的串行网络链，并非 18 秒都用于数学计算。

## 实现

- 受既有登录保护的 `/api/workspaces/{id}/readiness` 只读取工作区元数据，响应约 20 字节，不加载整份教材。
- HTML 入口检查已经进入校对阶段的工作区，提前并行预加载 Review 模块、CSS 与首屏所需字体；脚本放在 head-prepend，避免被前面的样式下载阻塞。
- 上传/设置阶段不预加载公式资源，相关浏览器回归继续通过。
- 校对页压缩标题与说明，完成后的步骤条隐藏，左右对照区使用大部分视口高度。
- 原图默认整页适配，ResizeObserver 按画布实际宽高计算缩放；手动放大请求高清图，适应画布恢复整页模式。来源框随同一坐标系缩放。
