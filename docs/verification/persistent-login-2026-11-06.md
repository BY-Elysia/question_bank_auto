# 持久化登录验证（2026-11-06）

## 原因与行为

旧实现的浏览器 Cookie 有到期时间，但服务端会话仅存在进程内存；更新或重启服务后，浏览器保留的 Cookie 无法通过验证。本次同时调整 Cookie 有效期和服务端会话存储。

- 默认从登录起保持 30 天，不保存密码到浏览器存储。
- Cookie 设置 Max-Age、Expires、HttpOnly、SameSite=Strict，生产环境设置 Secure。
- 服务端只持久化随机会话 token 的 SHA-256 摘要、到期时间及凭据指纹，文件位于持久化卷的 `access/sessions.json`；目录权限 0700，文件权限 0600。
- 登录轮换和退出撤销在持久化成功后才响应；退出以及账号或密码摘要变化会使相关旧会话失效。
- 保留单进程内存读取，避免每个请求读取磁盘；SessionStore 异步接口允许后续替换数据库适配器。当前文件适配器不能供多个进程共享写入。

首次从旧版本升级需重新登录一次；之后关闭浏览器、更新应用或重启容器可继续使用会话，直到到期或主动撤销。
