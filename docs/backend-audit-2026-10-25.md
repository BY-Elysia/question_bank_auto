# 后端可用性与架构检查（2026-10-25）

## 结论

当前单工作区后端的课本 PDF → JSON、可视化资源、人工编辑、模型核对/修复、缺失答案补全、候选审批和版本恢复链路已验证。没有增加前端或用户管理功能。

检查时原有目录虽已分模块，但应用层仍直接操作文件、HTTP 响应及具体实现。本轮修正了这些依赖，采用可替换端口与统一装配入口；数据库替换和新增 AI Skill 均有可执行测试。

## 发现与修正

| 问题 | 修正 |
| --- | --- |
| 仓储接口暴露 root/dir/atomic，业务必须了解文件布局 | 拆成 BookRepository 与独立资源接口，仓储接口只包含领域数据操作 |
| 上传用例直接使用 fs/path，导出用例依赖 Express/Archiver | 文件、页图和 ZIP 放到适配器，应用层返回流，HTTP 层转换响应 |
| Controller 读取具体 BookStore | 经 TextbooksService / JobsService 读取 |
| 调度器依赖具体提取/修复工作流 | 注入 JobHandler 映射，在 services.ts 组合解析与审核 |
| Skill 执行器固定六个 ID，并直接读写工作目录 | 独立 SkillCatalog、RunRecords、ModelClient 接口，执行器支持新增包 |
| Job 领域反向导入 AI 工作流的范围 schema | Range 移至课本领域 |
| 重复创建课本可能改写修订零 | 创建校验放在写入前，并串行拒绝重复 ID 与非零初始修订 |
| 真实模型把单题共享题干当章节/标题 | 结构与边界 Skill 明确“单题题号、共享题干、子问为一体”，版本升为 1.1.0 |
| 无匹配原文答案被模型报错，阻止缺失答案生成 | 区分确定无匹配与归属不确定；前者正常返回空集合，后者保留人工校对问题，source-verify 升为 1.1.0 |

## 自动化验证

`npm run check` 包括构建、22 个接口的 OpenAPI 检查、TypeScript 类型检查，以及 32 项自动化测试。

- 工作流：正式页队列、跨页 GROUP、预读约束、遗漏重试、失败检查点、重启恢复、取消、局部重跑范围扩展。
- 答案与审核：原文答案优先、仅填缺失子问、重复/越界输出拒绝、原文不确定时暂停生成、正常无匹配时继续生成、候选隔离、冲突拒绝、人工来源标记及版本恢复。
- HTTP 集成端测：真实 PDF、Poppler PNG、HTTP 路由、任务、审批、JSON/ZIP 内容；模型响应可控，包含坏 JSON 重试。
- 适配器：Responses/Chat HTTP 协议、429 重试和取消；JSON/真实 SQLite 仓储的回滚、并发更新、修订不可变、重复创建和删除保护。
- 架构扩展：同一 HTTP/业务流程注入 SQLite；动态新增章节总结 Skill；替换任务处理器。架构测试约束分层依赖和源码文件长度。

SQLite 是测试适配器，使用真实 SQL 事务和 JSON 列，证明接口替换可行；没有宣称已完成生产 PostgreSQL 表结构、迁移或索引。

## 真实模型 HTTP 端测

模型：`doubao-seed-2-0-pro-260215`，火山方舟 Responses 接口。密钥仅用于本地进程验证，不进入仓库、日志或报告。

样本为原创两页算术 PDF：矩形长 4、宽 3，Exercise 1 的两个子问跨页，Exercise 2 的原文答案为 5。真实调用链路验证结果：

| 检查 | 结果 |
| --- | --- |
| 上传与分页 | 2 页，按需生成 PNG |
| 章节与跨页识题 | 1 个章节；Exercise 1 为 GROUP，2 个子问，保留两页来源与共享条件 |
| 缺失答案 | 生成面积 12、周长 14，均为 ai_generated，审批前不进入正式内容 |
| 原文答案关联 | 独立答案块中的 5 通过 source 候选关联，没有被生成答案覆盖 |
| 真实模型核对 | 任务 completed，无问题 |
| 真实模型修复 | 将人为写入的错误 OCR 哨兵恢复为矩形条件的原文候选；正式内容不自动改变 |
| 审批、并发与版本 | 接受答案、拒绝修复、过期 expectedRevision 返回 409、恢复旧内容并新增修订 |
| 可视化与导出 | 两张有效 PNG；ZIP 含 source.pdf、textbook.json、两张 PNG |

修正后的解析阶段调用模型 11 次，后续核对/修复调用 2 次，合计返回用量 44,623 tokens。全链路按同一课本分段执行：首个测试脚本误将“原文答案必须内嵌在题目”当作断言，因此在解析完成后停止；修正为支持独立答案块的候选关联后，复用该课本完成后续 HTTP 检查。业务解析任务没有失败；对应记录见 [验证摘要](verification/live-2026-10-25.json)。

可复跑命令：

```bash
npm run build
node --env-file=.env scripts/live-e2e.mjs
```

脚本默认从新 PDF 上传开始。对已完成解析、尚未审批答案的测试样本，可同时设置 `LIVE_WORKSPACE_ROOT` 和 `LIVE_RESUME_BOOK_ID` 复查解析结果并继续后续步骤。报告及工作区留在打印出的临时目录，方便追溯。

## 后续扩展与尚未验证的范围

- 新课本 AI 功能通过 Skill + 输出 schema + 应用用例/JobHandler 接入；新增公开任务种类仍须修改请求契约、生成 OpenAPI 并测试。
- 外部数据库读取通过所属业务模块的查询端口接入；替换课本元数据则实现 BookRepository。模型不直接执行 SQL。
- 与课本无关的 AI 能力建立自己的领域与上下文，复用模型端口；当前 SkillContext 仍以课本/任务为中心。
- 当前只验证单进程工作区。多实例需要数据库事务、任务租约/队列和独立 worker，不能只更换数据库就直接多副本部署。
- 原创两页样本证明接口和业务闭环，不代表复杂中文教材、多栏扫描件、长表格或整本教材的识别准确率；需要实际教材回归集继续评估。
- 本轮验证在本机 Node/Poppler 环境执行，没有重新验证 Docker 镜像构建及容器部署。

详细边界和接入位置见 [架构说明](architecture.md)。
